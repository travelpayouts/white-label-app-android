# Настройка White Label приложения (Android)

Всё, что вы меняете под себя, лежит в каталоге `config/`. Правите его,
запускаете одну задачу Gradle, собираете.

```
config/
  app_config.json          все настройки — идентификаторы, тексты, цвета, вкладки
  google-services.json     ваш файл Firebase (обязателен)
  icons/                   иконка приложения, иконки вкладок
  images/                  фоновое изображение экрана поиска
  strings/                 ваши формулировки вместо текстов SDK
```

Порядок важен: **заполнить конфиг → положить свой файл Firebase → выполнить
`./gradlew parseConfig` → собрать.** `parseConfig` генерирует из вашего конфига
идентификатор приложения, названия, цвета, иконки и вкладки. Правка
`app_config.json` без запуска этой задачи в собранном приложении ничего не
меняет.

## Как читать это руководство

Каждое поле описано по коду, который его читает. Где ключ в шаблоне есть, а
эффекта не даёт, так и написано — см.
[Ключи, которые ни на что не влияют](#ключи-которые-ни-на-что-не-влияют).
Догадываться ни о чём не придётся.

Значения, которые зависят от языка, выглядят так: `base` — язык по умолчанию,
`localized` — переводы:

```json
{
  "base": "en",
  "localized": { "en": "My App", "ru": "Моё приложение" }
}
```

## `base_configuration`

| Поле | Обязательно | Что делает |
|---|---|---|
| `identifier.android.id` | да | Идентификатор приложения, например `com.mycompany.travel`. Не меньше двух сегментов через точку, каждый начинается с буквы и состоит из букв и цифр. Подчёркивания и дефисы отвергаются: генераторы подставляют это значение регуляркой `[0-9A-Za-z.]` — в `app_version.properties`, в строку `package` файла `StartActivity.kt` и в импорт в `TravelAppMessagingService.kt`, — и другой символ испортит их при следующем прогоне. Если в вашем опубликованном приложении в идентификаторе есть подчёркивание, сообщите нам до перехода — сменить его после публикации в Play нельзя |
| `identifier.android.versionName` | да | Версия для стора, например `1.0.0` |
| `identifier.android.versionCode` | да | Код версии, целое положительное число |
| `display_name` | да | Название приложения под иконкой (локализуемое) |
| `booking_review_request_frequency` | нет | Как часто просить оценить приложение; `0` — не просить |

## `constants`

| Поле | Что делает |
|---|---|
| `marker` | Ваш маркер Travelpayouts — на него начисляется вознаграждение. `parseConfig` предупредит, если пусто |
| `api_key` | Ваш ключ API Travelpayouts. Без него поиск билетов возвращает ошибку. `parseConfig` предупредит, если пусто |
| `client_device_host` | Идентифицирует ваше приложение в запросах SDK, уходит в заголовке `Referrer`. `parseConfig` предупредит, если пусто |
| `policy_url` | Ссылка на политику конфиденциальности (локализуемое) |
| `feedback_email` | Адрес для пункта «Связаться с нами» на экране информации. Оставите пустым — пункт исчезнет |
| `feedback_theme` | Тема этого письма. Пусто — будет `App Feedback` |
| `app_store_link` | Ссылка для пункта «Поделиться приложением». Пусто — подставится адрес Google Play по идентификатору приложения |
| `sharing_data.sharing_link` | Базовый адрес ссылок, которыми делятся из приложения. SDK приклеивает к нему `/?flightSearch=...`, поэтому нужен полный адрес со схемой (`https://example.com`), а не голый хост |
| `sharing_data.handling_link` | Хост, по которому приложение перехватывает ссылки. `parseConfig` записывает его без `https://` в `handling_link.properties`, оттуда он подставляется в манифест как `android:host` фильтра deep links. Оставите пустым — перехват ссылок работать не будет. Запускать `parseConfig` после правки обязательно |
| `appsflyer_dev_key` | Ключ AppsFlyer. Не пользуетесь — оставьте пустым |

## `advertising`

Весь блок необязателен: с пустым `appodeal_api_key` реклама не
инициализируется, приложение собирается и работает без неё.

**После правки этого блока запуск `./gradlew parseConfig` обязателен.** Именно
этот блок решает, какие рекламные библиотеки попадут в сборку, — сборка читает
его напрямую. Задача `parseConfig` генерирует из него рекламные ресурсы (запись
AdMob в манифесте и `appodeal_config.xml`) и записывает отпечаток блока в
`advertising.properties`. Если конфиг поправлен, а задача не запущена, сборка
останавливается: сгенерированные ресурсы больше не соответствуют конфигу —
раньше в такой ситуации приложение молча собиралось со старыми.

`advertising.properties` — сгенерированный файл, а не настройка: строка
`adsMode` в нём справочная, её правка ни на что не влияет.

**`parseConfig` и `verifyAdvertisingWiring` несовместимы с configuration cache.**
Если вы включили `org.gradle.configuration-cache`, запускайте любую из этих задач
с `--no-configuration-cache`. Обычные сборки кэш не ломает: он сохраняется,
переиспользуется и корректно пересчитывается при правке конфигурации.

**`parseConfig` нельзя запускать в одной команде со сборкой.** Задача пишет
`app_version.properties` и `handling_link.properties` во время выполнения, а
сборка читает оба файла на этапе конфигурации, который идёт раньше, — такая
команда собрала бы приложение со старыми значениями. Сборка на этом
останавливается. Если у вас в CI была строка вида
`./gradlew parseConfig assembleRelease`, разделите её на две.

Проверить, что реклама действительно подключилась, можно по дереву
зависимостей, а не по тому, что задача отработала без ошибок:

```bash
./gradlew verifyAdvertisingWiring
```

Задача резолвит дерево зависимостей релизной сборки и показывает, какие
адаптеры Appodeal в него реально попали, — то есть отвечает на вопрос, на
который зелёный `parseConfig` не отвечает.

Есть ещё параметр `-PadsMode=none|appodeal|appodeal_admob`: он подменяет режим
для этой одной проверки, не трогая конфигурацию. Он нужен, чтобы проверить
подключение до того, как заполнены ключи; со своими ключами запускайте задачу
без него, иначе проверите подменённую конфигурацию вместо своей. Любая команда
с `-PadsMode`, где запрошена не только `verifyAdvertisingWiring`, отвергается.

| Поле | Что делает |
|---|---|
| `appodeal_api_key` | Ключ Appodeal. Пустой — сетевые адаптеры в сборку не попадают. Само ядро Appodeal приезжает вместе с SDK всегда, но без ключа ничего не инициализируется |
| `google_admob_app_id` | Идентификатор приложения AdMob. Работает только вместе с заполненным `appodeal_api_key`: без него AdMob не подключается, потому что вся реклама идёт через Appodeal |
| `placements.air_ticket_placement_interstitial` | Полноэкранная реклама в поиске билетов. Обязательно, если заполнен `appodeal_api_key` |
| `placements.air_ticket_placement_banner` | Баннер в поиске билетов. Обязательно, если заполнен `appodeal_api_key` |

Заполните оба placement, как только включили рекламу. С заполненным
`appodeal_api_key` и пустым placement сборка не падает: `parseConfig` выводит
предупреждение и продолжает, потому что выпустить только один из двух форматов —
законный выбор. Что вы получите с пустым: адаптеры в сборке, полноэкранная
реклама не запрашивается ни разу, а для баннера пустое имя уходит в Appodeal, и
дальше решает он.

Placement не строкой — это ошибка, а не предупреждение: `123` или `true` доехали
бы до SDK как имена `"123"` и `"true"`. В сообщении указан полный путь поля, и
оно останавливает любую команду Gradle, включая синхронизацию проекта в IDE.

## `style`

| Поле | Значения | Что делает |
|---|---|---|
| `base_color` | hex, например `#d9332e` | Ваш основной цвет. Остальные оттенки выводятся из него |
| `corners_type` | `sharp`, `default`, `round` | Скругления кнопок и карточек |
| `icons_type` | `filled`, `line`, `tint` | Стиль иконок на экранах SDK |
| `palette` | `hsv` или любое другое | Как считаются производные оттенки. `hsv` — по модели HSV, любое другое значение (в шаблоне стоит `lab`) — по Lab, она ровнее держит воспринимаемую светлоту |
| `overridden_color` | объект | Задать конкретные оттенки вместо вычисленных |

Оттенки, которые можно закрепить в `overridden_color`:

```json
"overridden_color": {
  "ta_primary_light": "#d9332e",
  "ta_primary_dark": "#ff6b6b",
  "ta_primary_disable_light": "#f0a0a0",
  "ta_primary_disable_dark": "#8a4444",
  "ta_primary_pressed_light": "#b02a26",
  "ta_primary_pressed_dark": "#cc5555",
  "ta_surface_tint_light": "#fdf0f0",
  "ta_surface_tint_dark": "#2a1a1a"
}
```

Ключ, которого нет, вычисляется из `base_color`; указанный ключ берётся как
есть. Окончание `_light` — светлая тема, `_dark` — тёмная.

## `info_screen_config`

`items_to_display` — какие необязательные пункты показывать на экране
информации. Любые из: `about_app`, `rate_app`, `share_app`, `favorites`.

**`favorites` работает только вместе со вкладкой билетов.** Приложение включает
избранное, когда в списке вкладок есть `flights` **и** в этом списке есть
`favorites`. Без вкладки `flights` пункт не появится, как его ни указывай.

Остальные пункты этого экрана — региональные настройки, отображение цен,
«Связаться с нами» (появляется, если заполнен `feedback_email`) и
конфиденциальность — показываются всегда и отсюда не управляются.

`about_app_info` — тексты экрана «О приложении»: `description` и `partner_url`,
оба локализуемые. Третий ключ, `developer`, ни на что не влияет — см. ниже.

## `white_label_config.screens_to_display`

Вкладки нижней панели в том порядке, в котором вы их перечислите. Вкладка
информации добавляется в конец сама, её указывать не нужно.

Распознаются два типа:

- `flights` — поиск билетов;
- `other` — вкладка, открывающая веб-страницу.

```json
"white_label_config": {
  "screens_to_display": [
    { "type": "flights" },
    {
      "type": "other",
      "parameters": {
        "title": { "base": "en", "localized": { "en": "Deals", "ru": "Акции" } },
        "url":   { "base": "en", "localized": { "en": "https://example.com" } }
      }
    }
  ]
}
```

**Вкладок `other` может быть не больше двух.** На каждую сборка генерирует
ссылки на `ta_other<N>` — идентификатор экрана, граф навигации, заголовок,
адрес и иконку, — а в SDK этот набор есть ровно для двух: `ta_other1` и
`ta_other2`. Третья вкладка ссылается на несуществующие ресурсы, и сборка не
компилируется.

**Иконки этих вкладок берутся из файлов, а не из конфига.** Положите свои
`config/icons/ic_other_1.xml` и `ic_other_2.xml` — первый файл достанется первой
вкладке `other` в списке, второй — второй. Без файла вкладка получит иконку SDK
по умолчанию. Только векторные drawable (`.xml`).

Неизвестный `type` — например `hotels`, оставшийся с тех пор, когда в SDK был
поиск отелей, — пропускается без ошибки. Вкладкой он не станет.

## Иконки, фон и тексты

**Иконка приложения** — `config/icons/ic_launcher_foreground.xml` и
`ic_launcher_background.xml`. Нужны оба файла: если положить только один, шаг
пропускается целиком и остаётся иконка шаблона.

**Фон экрана поиска** — положите одно изображение в `config/images/`. Векторный
`.xml` имеет приоритет; иначе берётся `.png` или `.jpg` и масштабируется под
1440×3216. Не нужен свой фон — каталога `config/images/` быть не должно вовсе:
шаг тогда пропускается и остаётся фон SDK. Каталог, созданный пустым или с
файлом другого формата, приводит к падению `parseConfig` — это известный дефект
заготовки, а не ваша ошибка.

**Тексты** — `config/strings/<язык>/strings.xml` переопределяет формулировки
SDK. Каталог с именем `base` становится основным `values/strings.xml`, любое
другое имя — `values-<имя>/`. Ключи смотрите в ресурсах SDK: все начинаются с
`ta_`, кроме `app_not_found`. Каталог необязателен.

**Firebase** — `config/google-services.json`, ваш файл из консоли Firebase. В
нём должен быть клиент и для вашего идентификатора приложения, **и** для
отладочного варианта (`<ваш id>.debug`), иначе сборка упадёт позже с ошибкой
«No matching client found for package name». `parseConfig` проверяет это заранее
и называет недостающего клиента.

## Ключи, которые ни на что не влияют

Эти ключи есть в шаблоне или в модели конфигурации, но менять их бесполезно.
Перечислены, чтобы вы не тратили на них время.

| Ключ | Что происходит на самом деле |
|---|---|
| `constants.appstore_id` | Его вообще нет в модели конфигурации — при чтении файла молча отбрасывается. Ссылка на стор — это `app_store_link` |
| `info_screen_config.about_app_info.developer` | Есть в модели, но его никто не читает. На экране «О приложении» он не показывается |
| `screens_to_display[].parameters.id` | Игнорируется. Идентификаторы вкладок назначаются по порядку: первая `other` становится `other1`, вторая — `other2` |
| `screens_to_display[].parameters.icon` | Игнорируется. Иконка берётся из `config/icons/ic_other_N.xml`, см. выше |
| `identifier.apple.*` | Половина общей конфигурации, относящаяся к iOS. Android-сборка её не читает |
| `advertising.placements.hotels_*` | Остались от удалённого поиска отелей. При чтении файла отбрасываются |

## Сборка

### Требования

- Android Studio с установленной платформой Android SDK 36
- JDK 17
- Приложение работает на Android 8.0 (API 26) и новее

Проект собирается против Android 16 (API 36) — этого требует входящий в
поставку `travel-sdk`.

### Ключ подписи

Перед первой сборкой создайте в корне проекта файл `signing.properties`, иначе
сборка остановится с `FileNotFoundException` на этом файле. Шаблон —
`signing.properties.example`:

```
KEYSTORE_FILE_DEBUG=debug.keystore
KEYSTORE_FILE_PASSWORD_DEBUG=<пароль хранилища>
KEY_ALIAS_DEBUG=<алиас ключа>
KEY_PASSWORD_DEBUG=<пароль ключа>

KEYSTORE_FILE_RELEASE=release.keystore
KEYSTORE_FILE_PASSWORD_RELEASE=<пароль хранилища>
KEY_ALIAS_RELEASE=<алиас ключа>
KEY_PASSWORD_RELEASE=<пароль ключа>
```

Пути к хранилищам — относительно корня проекта. Ни `signing.properties`, ни
файлы хранилищ в git не попадают: `.gitignore` покрывает `signing.properties`,
`*.keystore` и `*.jks`. Он не покрывает хранилище, которое уже закоммичено, и
другие расширения вроде `.p12` и `.bks` — проверьте свою копию командой
`git ls-files | grep -i -E 'keystore|signing|\.(jks|p12|bks)$'`.

Если хранилища ещё нет:

```bash
keytool -genkeypair -v -keystore release.keystore -alias <алиас> \
  -keyalg RSA -keysize 2048 -validity 10000
```

### Команды

```bash
./gradlew parseConfig                 # применить конфигурацию — после каждой правки
./gradlew :app:assembleBasicDebug     # отладочная сборка
./gradlew :app:assembleBasicRelease   # релизная сборка
```

APK появится в `app/build/outputs/apk/basic/<тип сборки>/`.

Из Android Studio: один раз запустите `parseConfig` на панели Gradle, затем
собирайте с выбранным вариантом `basicDebug` или `basicRelease`.

Вопросы — support@travelpayouts.com.
